# สัญญาร่วมของ checkwork ทุกตัว

> agent ตรวจงานทั้ง 7 ตัวอ่านไฟล์นี้แทนการเขียนกฎชุดเดียวกันซ้ำในตัวเอง
> แก้ที่นี่ที่เดียว มีผลกับทุกตัวพร้อมกัน

## 1. อ่านอย่างเดียว

**ห้ามแก้ไฟล์ใด ๆ** ไม่มี `Write`/`Edit` ให้ใช้อยู่แล้ว และห้ามเลี่ยงด้วย `Bash`
(`>` `>>` `sed -i` `tee` `python -c "open(...,'w')"` ฯลฯ) แม้ปัญหาจะเล็กแค่ไหน

เหตุผล: ประตูตรวจที่แก้งานเองได้ = ไม่มีประตู ผู้ตรวจกับผู้ทำต้องแยกกัน
งานแก้เป็นของ writer เสมอ — หน้าที่ของ checkwork คือ **ชี้ให้ชัดว่าต้องแก้อะไรตรงไหน**

## 2. อ่านบัตรผลตรวจของเครื่องก่อนลงมือ  ★

`validate_spec.py --report` เขียน **`{BASE}_gate.md`** ไว้ให้แล้ว (path อยู่ที่ `paths.py`
คีย์ `gate_md`) **อ่านไฟล์นี้เป็นอันดับแรก**

ทุกอย่างที่อยู่ในบัตรนั้น **เครื่องนับให้แล้วพร้อมค่าที่วัดได้จริง — ห้ามนับซ้ำ**
เช่น โควตาความยาก 15/8/7 · การกระจายเฉลย ก8 ข8 ค7 ง7 · เวลากิจกรรมรวม 50/50 นาที ·
หน้าปกกี่แถวและตรงไฟล์อ้างอิงไหม · ทักษะ 8C ครบไหม

เอาแรงทั้งหมดไปตรวจสิ่งที่เครื่องตรวจไม่ได้แทน
- **ความถูกต้องของเนื้อหา** — ผิดวิชา ผิดข้อเท็จจริง คลาดเคลื่อน
- **ความสอดคล้องภายใน** — ประโยคหนึ่งขัดกับตัวอย่างของเอกสารเอง
- **ความเหมาะกับระดับชั้น** — ศัพท์/ความซับซ้อนเกินหรือต่ำกว่าชั้น
- **คุณภาพเชิงการสอน** — กำกวมจนตีความได้สองทาง · อุปมาที่พาไปเข้าใจผิด ·
  ตัวลวงสองตัวที่หมายถึงสิ่งเดียวกัน · จุดประสงค์ที่ไม่มีเครื่องมือวัด

## 3. อ่านบัตรขอบเขตคาบ  ★

**`{BASE}_scope.md`** (`paths.py` คีย์ `scope_md`) บอกว่าคาบนี้ต้องส่งมอบอะไร
เรียนอะไรไปแล้ว และ **อะไรที่ยังไม่ถึงคิว — ห้ามล้ำ**

- **COMP = สาระสำคัญ/จุดประสงค์ประจำคาบ (ระดับคาบ)** ต้องส่งมอบครบ 100%
- **OBJ = จุดประสงค์ประจำหน่วย (ระดับหน่วย) กินหลายคาบ** —
  **ห้ามสั่งให้เพิ่มจนงานชิ้นเดียวรับ OBJ ครบทั้งหน่วย** นี่คือสาเหตุของรอบแก้
  ที่แพงที่สุดที่เคยเกิด (สั่งเขียน C1 ใหม่ทั้งฉบับเพราะเข้าใจ COMP ผิดระดับ)
- เนื้อหาที่อยู่ในหัวข้อ "ยังไม่สอนในคาบนี้" = ห้ามโผล่ในงาน แม้จะช่วยให้เข้าใจง่ายขึ้น

- เนื้อหาต้นทางให้อ่าน **`{BASE}_srcpack.md`** ก่อนเสมอ (~2.1k โทเคน)
  เปิด C1 ฉบับเต็ม (~8.1k) เฉพาะเมื่อ srcpack ไม่พอจริง ๆ
- **ห้าม `Read` ไฟล์หลักสูตร `course-structure-*.md` ทั้งไฟล์** (ใหญ่ถึง 51 KB)
  ข้อมูลที่ต้องใช้อยู่ในบัตรขอบเขตคาบแล้ว ถ้าต้องการเพิ่มให้เรียก
  `eduone-py no_to_token.py <gradeSlug> <subjectSlug> <No>` ซึ่งคืนเฉพาะของคาบนั้น

## 5. รูปแบบคำตอบ (บังคับ เหมือนกันทุกตัว)

บรรทัดสุดท้ายต้องเป็นบรรทัดใดบรรทัดหนึ่งนี้ **ตรงตัวอักษร**

```
VERDICT: PASS
VERDICT: FAIL
```

ถ้า FAIL ตามด้วยหัวข้อ `รายการแก้:` และรายการที่ **ลงมือแก้ได้ทันที**
บรรทัดละหนึ่งเรื่อง เรียงจากรุนแรงที่สุดลงมา

```
รายการแก้:
- [<ที่อยู่>] <ต้องแก้อะไร ให้เป็นอะไร>
```

`<ที่อยู่>` ใช้แบบที่ตรงกับผลผลิตของตัวเอง เช่น `[ข้อ 7]` `[L1][หัวข้อ 4]` `[C2][ย่อหน้า 3]`
`[slides C1][หน้า 5]` `[STEP 3]` — ให้ writer เปิดไปที่จุดนั้นได้โดยไม่ต้องค้น

**ห้ามตอบแค่ "ดูดีแล้ว"** ต้องเดินครบ checklist ของตัวเองก่อนสรุปเสมอ
และ **ห้ามรายงานปัญหาที่บัตรผลตรวจของเครื่องบอกว่าผ่านแล้ว**

### 5.1 ★ เขียนรายการแก้ลงไฟล์ แล้วคืนกลับมาแค่สรุป

**เมื่อ FAIL ให้เขียนรายการแก้ฉบับเต็มลงไฟล์ก่อน** ที่ `review_md` จาก `paths.py`
ผลผลิตที่มีหลายไฟล์ให้เติม tag: `{BASE}_gate_L1_review.md` · `{BASE}_gate_C1_review.md`
(ตั้งชื่อให้ตรง pattern `*_gate_*.md` ที่ `.gitignore` ครอบไว้ — สร้างใหม่ได้เสมอ ไม่ต้อง track)

แล้ว**คำตอบที่คืนกลับมาให้สั้น** — เอาแค่นี้พอ

```
เขียนรายการแก้ไว้ที่ <path ของ review_md>
สรุป: <ต้องแก้ N ข้อ · ข้อที่หนักที่สุดคืออะไร ในหนึ่งบรรทัด>
VERDICT: FAIL
```

จากนั้น orchestrator จะ **ส่ง path ของไฟล์นี้ต่อให้ writer ไปอ่านเอง**

**ทำไม** — ของเดิม orchestrator ต้องพิมพ์รายการแก้ยาว ๆ ลง prompt ทุกครั้งที่ส่งกลับให้ writer
(รอบ M1-Math_U1_1_2 เกิดขึ้น 7 ครั้ง) ซึ่ง **กินบริบทของแม่และค้างอยู่ตลอด pipeline**
และเป็นการคัดลอกด้วยมือ ซึ่งตกหล่นเมื่อไร writer ก็แก้ไม่ครบตามนั้นทันที
นี่คือกฎ "ส่ง path ไม่ส่งเนื้อหา" ของ CLAUDE.md ที่ยังไม่เคยใช้กับผลของ checkwork

**PASS ก็เขียนไฟล์** (บันทึกว่าตรวจอะไรไปบ้าง) แต่คืนกลับมาแค่ path + `VERDICT: PASS`
ข้อสังเกตที่ไม่บล็อกให้อยู่ในไฟล์ ไม่ต้องคืนกลับมา

## 6. แบบแผน path

ทุก path resolve จาก `eduone-py paths.py <gradeSlug> <subjectSlug> <No>` เท่านั้น
**ห้ามประกอบ path เอง** ไฟล์ของแต่ละผลผลิตอยู่ในโฟลเดอร์ของตัวเองใต้ `<topic_dir>`
(`1. Content/` `2. LessonPlan/` `3. Exercise/` `4. Slides/` `5. Video/` `6. Song/`)
ส่วนบัตรขอบเขตคาบและบัตรผลตรวจอยู่ที่ราก `<topic_dir>` เพราะใช้ร่วมกันทุกผลผลิต
